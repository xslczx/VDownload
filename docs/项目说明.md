# VDownload 项目说明

> 本文档基于对代码库的实际阅读整理，覆盖项目定位、架构、核心流程与关键实现细节。

## 1. 项目简介

VDownload 是一个 Android 应用，用于**解析并下载抖音等平台的公开视频/图集链接**。核心体验是：复制分享链接 → 打开 App → 自动读取剪贴板并识别媒体链接 → 解析直链 → 下载图片/视频/音频到本地 → 入库记录、可预览、可导出系统相册。

- 应用 ID：`com.xslczx.vdownload`
- 版本：1.2（versionCode 3）
- 语言：Kotlin 为主（含少量 Java：`ClipboardUtils`、`TabEntity`、`CMAppGlideModule`）
- minSdk 26 / targetSdk 32 / compileSdk 35

## 4. 核心流程（剪贴板 → 本地文件）

流程入口在 `DouyinViewModel.processClipboardContent()`：

1. **提取链接**：`ClipboardUtils.extractCleanUrl()` 从剪贴板文本清洗出 URL（`normalizeUrl`）。
2. **去重防抖**：
   - 内存层：`processingUrls`（ConcurrentHashMap.newKeySet）在流程开始即占位，**入库后才释放**——防止权限弹窗关闭、切后台返回、设置页返回等多重 onResume 造成的重复触发；
   - 数据库层：`getLastByUrl(url)` 命中则直接视为完成，不重复下载。
3. **解析**：调用第三方解析 API `https://api.spapi.cn/get?appkey=...&url=...`（appkey 硬编码在 `DouyinViewModel` 的 companion 中），Moshi 反序列化为 `DouyinApiResponse{ data: { title, image, atlas[], video, url } }`。
4. **收集媒体**（`collectMedia`，优先级）：
   - 有 `video` → 只下视频；
   - 否则有 `image` → 下单图；
   - 否则下 `atlas` 图集。
5. **并发下载**（`downloadAllMedia`，并发度 3）：
   - 每个任务先 HEAD 请求拿 Content-Type / Content-Disposition，用于类型检测与扩展名推断；
   - 下载写入 cacheDir 下的 `.part` 临时文件，成功后 rename/copy 到目标位置；
   - 失败自动重试 2 次，退避 `300ms × (attempt+1)`；协程 `CancellationException` 原样上抛不当作业务失败；
   - 分目录存储：视频 → Movies、图片 → Pictures、音频 → Music、未知 → Downloads；无写权限时回退 App 私有目录 `getExternalFilesDir`；
   - 汇总各任务进度计算总百分比，回调给 UI 显示「正在下载 N%」。
6. **入库与导出**（`handleDownloadResults`）：
   - 任一文件失败则整体报「下载失败」，**不扫描相册**（避免相册出现文件而应用内无记录）；
   - 全部成功后 `MediaScannerConnection.scanFile` 扫入系统相册；
   - Room 插入 `DouyinVideo(url, title, savedImagePaths, savedVideoPath)`，路径多个以逗号拼接；
   - 回调 onComplete 后才释放 `processingUrls` 占位。

各阶段通过 `onStep` 回调向 UI 推送状态文案：正在提取链接 → 正在解析链接 → 正在下载 N% → 下载完成 → 正在保存记录。

## 5. 页面与交互

- **MainActivity**：底部 Tab（首页 / 记录 / 我的），flycoTabLayout + Fragment 切换，带滑动动画（res/anim）。
- **HomeFragment**：
  - 输入框监听 + onResume 检查剪贴板（受设置页「自动解析」开关控制）；
  - 存储权限用 `registerForActivityResult(RequestPermission)` 处理（注释说明：Activity 分发的 onRequestPermissionsResult 在 Fragment 收不到），授权后继续挂起的解析；
  - 长按记录项弹 MessageDialog 确认删除（同时删 adapter 条目和数据库记录）。
- **RecordFragment**：展示全部记录；`computeMediaStats` 在 IO 线程按**文件头**（`MediaTypeDetector.detect(file)`）统计视频/图片/音频数量。
- **SettingsActivity**：存储权限申请入口、自动解析开关。

## 6. 权限与兼容

- `INTERNET`；`READ/WRITE_EXTERNAL_STORAGE` 限定 `maxSdkVersion=32`（API 33+ 由 READ_MEDIA_* / 分区存储取代）；
- Manifest 声明 `requestLegacyExternalStorage="true"`（targetSdk 32 下的兼容策略）；
- FileProvider（`${applicationId}.fileprovider`）用于文件分享/预览。

## 7. 构建与签名

- 根目录 `keystore.properties`（不入库，有 `.example` 模板）提供正式签名；**文件不存在时 release 自动回退 debug 签名**，保证克隆后随时可打包。
- `app/scan.gradle` 被应用（`apply(from=...)`），配合根目录 `scan-result.json`，疑似接入了某种依赖/代码扫描任务。
- `settings.gradle.kts` 使用 `RepositoriesMode.PREFER_PROJECT`：允许全局 init 脚本（如阿里云镜像）注入仓库优先生效，无全局脚本时仍走 google()/mavenCentral()。
- 产物路径：`app/release/app-release.apk`。
- release 构建关闭 lint 强制（`checkReleaseBuilds=false`、`abortOnError=false`），未开混淆（`isMinifyEnabled=false`）。

## 8. 值得注意的设计点（源码注释佐证）

1. **双层去重**：内存占位 + 数据库查重，且释放时机刻意放在入库之后（`DouyinViewModel.kt` 注释）。
2. **相册一致性**：只有全部下载成功才 `scanFile`，保证相册与应用记录一一对应。
3. **OkHttp / Moshi 全局复用**：避免重复分配连接池、线程池；Moshi 反射工厂必须 `addLast` 挂链尾，否则遮蔽内建与 codegen 适配器。
4. **`.part` 临时文件 + rename**：下载不完整文件不会污染目标目录。
5. **取消语义严谨**：`CancellationException` 在网络与下载两处都单独上抛，不进重试/失败分支。
6. **媒体统计读文件头**而非信扩展名，统计在 IO 线程执行。

## 9. 可改进方向（个人观察）

- 解析 API 的 appkey 硬编码在源码中，且依赖单一第三方服务（spapi.cn），可用 BuildConfig/本地配置注入并考虑降级源；
- `DouyinViewModel` 为 AndroidViewModel 但解析 API 与业务耦合较深，可抽 Repository 层；
- targetSdk 32 较旧，升级到 34+ 需处理分区存储（当前依赖 legacy external storage）与照片权限；
- 包名目录 `databse` 拼写应为 `database`；
- 无单元测试/instrumentation 测试（testInstrumentationRunner 仅是默认声明）。
